# بحث Supabase الموثق — مادة خام لتصميم قاعدة اوس (جُمع 2026-11-23)

## الخطة المجانية — الأرقام
- السعر $0 · قاعدة البيانات **500MB** للمشروع · تخزين ملفات 1GB · Egress ‏5GB (+5GB cached) · ‏50,000 MAU · **مشروعان نشطان** بحد أقصى (الموقوف لا يُحسب) · Edge Functions ‏500k/شهر · Compute: Shared CPU / 500MB RAM (Nano).
- المصادر: supabase.com/pricing + supabase.com/docs/guides/platform/billing-on-supabase (محدّثة 2026-09-17).

## التجميد (المصدر: supabase.com/docs/guides/platform/free-project-pausing — محدّثة 2026-09-22)
- المشروع قليل النشاط على مدى **7 أيام** بيقف. «النشاط» = طلبات مستخدمين حقيقية للداتابيز (كام طلب يوميًا بيكفي عادة) — العتبة الدقيقة غير منشورة.
- تحذيران بريديان: قبل الوقوف بنحو أسبوع + تأكيد عند الوقوف. وهو واقف: أي طلب API بيرد **HTTP 540**.
- الاستعادة من الداشبورد (Resume) — نص الوثيقة الحالي: نافذة **سنة**؛ ⚠️ تناقض داخلي: عنوان قسم نفس الصفحة وتشانج لوج 2024 بيقولوا 90 يوم — الافتراض الآمن = الأقصر.
- استعادة برمجية: `POST /v1/projects/{ref}/restore` (Management API، صلاحية projects:write).
- المشاريع المدفوعة لا تقف أبدًا لعدم النشاط. والمشروع المستعاد بيقف تاني لو الأسبوع اللي بعده هادي.

## pg_cron ضد التجميد
- لا نص رسمي إنه بيتحسب نشاطًا. أدلة تشغيل منشورة (LetRelay وغيرها): النشاط المطلوب خارجي؛ وpg_cron بيموت مع الوقوف ولا يستأنف ما فاته ولا يعوّضه.
- ⚠️ ادعاء متضارب وحيد (Runhooks) إن pg_cron اليومي «قد» يُحسب — غير موثق رسميًا وغير قابل للاعتماد. **الخلاصة المعتمدة في التصميم: النبضة خارجية حصرًا.**

## النسخ الاحتياطي (المصدر: supabase.com/docs/guides/platform/backups)
- **المجاني: لا نسخ تلقائي متاح للتنزيل إطلاقًا** — التوصية الرسمية: تصدير ذاتي دوري بـ`supabase db dump`.
- Pro ‏($25/شهر للمنظمة، يشمل $10 رصيد Compute): نسخ يومي باحتفاظ **7 أيام** · قاعدة 8GB · egress ‏250GB · لا تجميد. Team: ‏14 يوم.
- PITR إضافة مدفوعة (RPO ~دقيقتين): 7 أيام ~$100/شهر وطالع — خارج نطاقنا حاليًا.
- النسخ (يومي/PITR) لا تشمل ملفات Storage.

## ممارسات إبقاء المشروع حيًا (منشورة ومتداولة)
- مجدول خارجي (GitHub Actions cron غالبًا) بينفذ قراءة حقيقية لصف من جدول عبر REST بمفتاح anon — قراءة `/rest/v1/` لوحدها لا تكفي (بتثبت البوابة بس).
- الإيقاع الموصى به **يومي** (هامش جوه نافذة الـ7 أيام؛ جدولة GitHub ممكن تتأخر/تتفوّت).
- كشف الوقوف: Polling بيفرّق 200 (صاحي) من 540 (واقف) + تنبيه — الاستعادة نفسها لا تتم إلا داشبورد/Management API.
- ممنوع مفتاح service_role في أي workflow نبض — anon يكفي.

## غير المُتحقق منه صراحةً
عتبة النشاط الدقيقة (غير منشورة أصلًا) · نافذة الاستعادة (تناقض 90 يوم/سنة في وثائق Supabase نفسها) · ادعاء «نسخ مجانية موجودة وتتفتح بالترقية» (مصدر ثانوي وحيد — مرفوض كأساس).
