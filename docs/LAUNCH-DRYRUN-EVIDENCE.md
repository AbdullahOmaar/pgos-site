## ٦. محاكاة فك التشفير التكاملي (End-to-End Vault Simulation)

أُجري اختبار محاكاة لفك التشفير وحقن البيانات في الذاكرة عبر Node.js:
1. قراءة `public/data/site-data.json` المُنقّى (5,668 بايت).
2. توليد زوج مفاتيح P-256 لجهاز تجريبي واستخراج بصمته (`fp`).
3. تغليف اللقطة للجهاز التجريبي عبر خوارزمية `P256-ECDH+HKDF-SHA256+A256GCM`.
4. فك تشفير اللقطة باستخدام المفتاح الخاص للجهاز ← **تطابق بايتي بنسبة 100% (true)**.
5. اختبار فك التشفير بجهاز غير مسجل ← **رُفض مباشرة برمز `NO_WRAP`**.
6. التحقق من صحة كائن البيانات المفكوك ← JSON سليم ومكتمل، ويحمل وسم `sanitized: true`.

## ٧. ملاحظات يوم الإطلاق (Launch-Day Operational Notes)

توثيق دقيق لكافة الملاحظات والالتفافات المستخلصة لضمان إطلاق ميكانيكي سلس:

1. **أهمية أمر `build:encrypted` في النشر النهائي:**
   * في الخطوة (٢) من دفتر التشغيل، أمر `npm run build` العادي يُبقي على ملف `dist/data/site-data.json` داخل مجلد الإخراج؛ في بيئة المُنقّى هذا آمن تمامًا لأن البيانات تجريبية (DEMO فقط).
   * **ملاحظة تشغيلية حاسمة:** في الخطوة (٤) عند النشر الحقيقي، **يجب حصرًا** استخدام `npm run build:encrypted` لأنه يحذف الملف الواضح آليًا ويفحص غياب أي علامات، لمنع تسرب الملف المقروء إلى خادم Vercel بالخطأ.
2. **سلوك خوادم التطوير الثابتة مقابل Vercel (SPA Rewrites):**
   * الخوادم الثابتة البسيطة (مثل `python3 -m http.server`) لا تعيد توجيه مسارات المتصفح العميقة (مثل `/decisions`) إلى `index.html` فتعيد خطأ 404.
   * **ملاحظة تشغيلية:** تم التحقق من احتواء `vercel.json` على قاعدة `rewrites` الصحيحة:
     `{"source": "/((?!data/|assets/|favicon.svg).*)", "destination": "/index.html"}`
     وهذا يضمن أن Vercel سيعيد توجيه كافة المسارات الـ 16 إلى `index.html` بسلاسة.
3. **توليد البيانات الحقيقية يوم الإطلاق:**
   * يوم الإطلاق الحقيقي يتطلب أولاً تشغيل `npm run data` (الذي يسحب من مصادر الحقيقة الكانونية) بدلاً من `npm run data:sanitize`.

## ٨. قائمة «ما لا يمكن بروفته إلا حيًا» (Live-Only Boundaries)

تحديدًا لحدود البروفة الصريحة وحماية للبيانات:

1. **إثبات الرفض على رابط حي (Live Rejection Proof):**
   * إثبات أن طلب رابط الموقع العام أو رابط `snapshot.enc.json` عبر الإنترنت ومن متصفحات مجهولة يقتصر على إعادة الشفرة والترويسات الأمنية المحددة في `vercel.json` (`Cache-Control: no-store`، `X-Robots-Tag: noindex, nofollow`...).
2. **تفعيل جهاز المالك الفعلي (Live Device Activation):**
   * توليد المفتاح من متصفح هاتف المالك عبر واجهة WebCrypto وتخزينه في IndexedDB بهاتفه، ثم إرسال كود التفعيل لتسجيله في المستودع.
3. **فك التشفير وعرض البيانات الحقيقية للمالك:**
   * رؤية المالك للموقع الحقيقي ببيانات الشركة وسجلاتها الـ 30 لأول مرة على شاشة هاتفه، وهو الشرط المسبق لقراري الإطلاق والتقاعد.
