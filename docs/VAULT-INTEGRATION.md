## كيف يسجّل المالك جهازه (3 خطوات)

1. افتح الموقع المنشور من الجهاز → «📱 تفعيل هذا الجهاز» — يتولّد مفتاح خاص لا يغادر الجهاز ويظهر **كود تفعيل** عمومي (ليس سرًا) + بصمة الجهاز.
2. ابعت الكود لأي وكيل في الشات.
3. الوكيل يضيف `{id, pub, fp}` إلى `tools/devices.json` ويشغّل `npm run data && npm run data:encrypt` وينشر — الموقع يفتح على الجهاز تلقائيًا بعدها.

استعادة جهاز: شاشة التفعيل تقبل استيراد مفتاح JWK خاص (ترحيل جهاز قديم). فقدان كل الأجهزة المسجلة = إعادة تفعيل جهاز من الخطوة 1 — البيانات تُعاد توليدها من مصادرها فلا فقدان دائمًا.

## كيف يُثبت الرفض لغير المسجّل

- **على الخادم لا يوجد إلا نص مشفّر:** `GET /data/snapshot.enc.json` يرجع JSON فيه `payload.ct` بترميز base64url فقط. تحقق فعلي أُجري 2026-11-22: العلامة النصية `3A-316` تظهر **14 مرة** في `site-data.json` الخام و**0 مرة** في `snapshot.enc.json`، ولا أي مفتاح JSON واضح (`records`/`ledger`/…) في الحزمة.
- **جهاز غير مسجّل يُرفض برمجيًا:** `unwrapSnapshot` يبحث عن تغليف يطابق بصمة مفتاح الجهاز؛ غير المسجّل لا يجد أي تغليف فيُرفض بخطأ `NO_WRAP` قبل أي فك تشفير — مثبت في `npm run vault:test`.
- **العبث يُرفض:** قلب بايت واحد في الحمولة يجعل AES-GCM يرفض الفك (`DECRYPT_FAIL`) — مثبت في الاختبار نفسه.
- **إثبات طرف-لطرف على الملف المنتَج فعليًا:** جُهّز جهاز مؤقت، شُفّرت اللقطة الحقيقية بـ `npm run data:encrypt` لمفتاحه، ثم فُكّت من الملف المكتوب بنفس وحدة `src/lib/vault.mjs` التي يستخدمها المتصفح: **201,421 بايت مطابقة بايتًا ببايت** للملف الأصلي، والـ JSON المفكوك يطابق شكل `SiteData`. (أُعيدت `tools/devices.json` بعدها إلى `test-device` وأُعيد التشفير.)
