## ١. ما هو الموقع — بجملة واحدة

مرآة قراءة واحدة، باحترافية تطبيق المدرس، تعرض حوكمة PGOS وسجل الشركة وتاسكات Linear وقرارات المقر وحالة الاكتمال والتقارير — **من مصادرها الكانونية نفسها، بلا نموذج بيانات موازٍ وبلا مصدر حقيقة جديد** (الموقع يعرض؛ لا يحكم ولا يكتب).

## ٢. مبادئ غير قابلة للتفاوض (من دراسة PGOS)

1. **نموذج البيانات = سجلات PGOS نفسها** (٩ أنواع) كما هي في `ops-system/pgos/records/` — لا اختراع صيغ جديدة.
2. **الحالات لا تُدمج:** IMPLEMENTED ≠ TESTED ≠ REVIEWED ≠ ACCEPTED ≠ DEPLOYED ≠ LIVE_VERIFIED — تُعرض كما هي من مصدرها.
3. **كل اعتماد معروض مربوط بمرجعه** (approval_ref) — كلمة APPROVED بلا مرجع تُعرض كادّعاء لا كحقيقة.
4. **البيانات INTERNAL:** لا بيانات حقيقية على أي رابط قبل إثبات بوابة وصول على الحافة (انظر المرحلة ٠).
5. **الانحرافات معلنة في الموقع نفسه** (D-1/D-2/D-3 + فجوات PGOS) — صفحة «التبنّي والانحرافات» جزء من المنتج لا ملحق خفي.
6. **صدق حالة التحقق:** «تحقق داخلي بالموقع» (كودنا) يُسمّى باسمه، ولا يُسمّى أبدًا «فاليديتور PGOS الأصلي».

## ٣. البنية التقنية (محسومة في وثيقة المعمارية)

- **المكدّس:** React 19 + TypeScript + Vite 8 + Tailwind v4 + React Router 7 — نفس إصدارات ومكونات وثيم تطبيق المدرس (RTL، IBM Plex Sans Arabic، داكن/فاتح) بهوية 3A (نيلي #3B3FA3/إنديجو، سماوي #00D2FF، كهرماني #FFA726 على كحلي عميق) — تُكيَّف متغيرات الثيم لهوية الشركة لا هوية تطبيق المدرس.
- **لا Supabase في المرحلة الأولى** (قراءة فقط، لا خلفية) — مشغلات إعادة النظر موثقة في وثيقة المعمارية.
- **البيانات:** خط توليد Python (stdlib فقط) يقرأ المصادر الكانونية ويُخرج JSON ثابتًا مختومًا ببصمة كل مصدر وختم حداثة:
  - `ops-system/pgos/records/*.json` → سجلات الحوكمة
  - `ops-system/ledger/company-ledger.jsonl` (+ تحقق السلسلة) → سجل الشركة
  - `ops-system/linear-sync/payload.json` → التاسكات والمشاريع (يُضاف لها مشروع PGOS نفسه)
  - `ops-system/guard/{state,alerts}` → حالة فحص الاكتمال وفجواته
  - قرارات المقر: تصدير/استخراج موسوم في بيئة التشغيل (المرحلة ٢) مع بديل ملفي آمن في المرحلة ١ — الاستخراج من نص حرّ هشّ ولا يُبنى عليه صامتًا
  - `ops-system/templates/` + السجل → التقارير
- **التحقق الداخلي:** إعادة تنفيذ قواعد فاليديتورَي PGOS (بنية + روابط عابرة + قواعد حالات) داخل خط التوليد — كودنا، يعمل ويُختبر عندنا، ونتيجته تُعرض في صفحة «حالة التحقق».
- **قاعدة النشر الآمن:** أي فشل تحقق (أولها كسر سلسلة الليدجر) يوقف التوليد/النشر، وتبقى آخر نسخة صالحة مع شارة قدم واضحة.

## ٥. المراحل وبواباتها

- **مرحلة ٠ — التأسيس والبوابة:** هيكل المشروع بنمط المدرس + الهوية + خط التوليد ببيانات حقيقية **محليًا فقط** + إثبات بوابة الحافة على نشر تجريبي بلا بيانات حقيقية (رفض غير المصرّح = دليل قبول المرحلة).
- **مرحلة ١ — قلب الحوكمة:** أقسام المرحلة ١ بالجدول، بيانات حقيقية خلف البوابة المثبتة، بوابات: `tsc -b && vite build` أخضر + lint + تحقق صف-بصف من بيانات التوليد ضد المصادر.
- **مرحلة ٢ — الاكتمال:** تاسكات + تقارير + سلطة + تبنّي + تسليمات/حوادث + قرارات المقر + ربط NotebookLM.
- **مرحلة ٣ — الصلابة:** مراجعة كود+أمان+معايير مستقلة، **اختبار كسر مقصود موثق** (كسر سلسلة في نسخة، حمولة Linear قديمة، حلقة اكتمال ناقصة، سجل بروابط مكسورة، محاولة وصول غير مصرّح) — كل كسر لازم يظهر كإنذار/رفض لا كنجاح صامت.
- **مرحلة ٤ — النشر والتحقق الحي:** نشر Vercel + تحقق حي من الموبايل خلف البوابة. **الإعلان/الإطلاق العام وتقاعد اللوحة: قرار مالك بعد رؤية الموقع حيًا** — لا يحدثان من المسار منفردًا.

## ٦. فجوات وحدود معلنة (لا تُخفى)

1. فاليديتورز PGOS الأصليون غير مشغّلين آليًا في هذه البيئة (قيد فحص مخاطر) — التحقق الداخلي بديل موثق التسمية، لا PASS مقنّع.
2. النسخة الحية من Engineering & Security Standards **غير موجودة فعليًا في فولدر المقر** لحظة كتابة المخطط (٤ مستندات فقط) — تُتابع كقيد ناقص عند مسار 3A-314؛ المخطط يلتزم بنسخة المعايير المعروفة من مسار تطبيق المدرس إلى أن تستقر في المقر.
3. دلالتا A0/A3 غير معرّفتين في وثائق PGOS — الموقع يعرض مستويات الاعتماد كما في السجلات ولا يخترع تعريفات؛ أي استخدام محلي يحتاج تعريفًا موثقًا أولًا.
4. بيانات ثابتة = حداثة بحدّ إيقاع المزامنة (Linear كل ساعتين، الحارس كل ساعة) — كل صفحة تحمل ختم «آخر تحديث» من مصدرها، لا ادعاء حيّة لحظية.
5. قيود الليدجر الـ backfilled أوقاتها تقريبية وموسومة كذلك في العرض.

## ٧. قرارات هذا المخطط (تُسجّل في سجل قرارات المقر)

1. اعتماد JSON الثابت المولّد مصدرَ عرض الموقع، ورفض API الحي من المتصفح نهائيًا.
2. بوابة حافة مثبتة شرط مسبق لأي بيانات حقيقية على رابط — وإثبات الرفض دليل قبول.
3. التحقق الداخلي المعاد تنفيذه بديلًا موثقًا عن تشغيل فاليديتورز الريبو في هذه البيئة، بتسمية صادقة.
4. الموقع قراءة فقط حتى إشعار مالك آخر — أي كتابة من الواجهة قرار جديد بسجل جديد.
